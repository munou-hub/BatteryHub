# BatteryHub（バッテリー集約アプリ）

複数の Android デバイスの電池残量を、同一 Wi-Fi（LAN）内でメイン端末（ホスト）に集約するアプリです。
ホスト／クライアントは**同一アプリ**で、設定画面から役割を切り替えます。

- パッケージ名: `jp.mk.batteryhub`
- バージョン: 1.5（versionCode 6）
- minSdk 26（Android 8.0）／ targetSdk 34（Android 14）
- 外部ライブラリ依存なし（Android フレームワークのみ、Java 実装）

## 仕組み

### 通信方式

- プロトコル: **UDP**（LAN 内のみを想定。暗号化・認証はなし）
- レポート用ポート: **47110/UDP**（固定）
  - クライアント → ホストへ JSON を送信
  - 形式: `{"type":"report","name":"Xperia 1 II","level":85,"charging":true,"ts":...}`
- ホスト自動発見ポート: **47111/UDP**（固定）
  - クライアントが `{"type":"discover"}` をブロードキャスト（255.255.255.255 とサブネットブロードキャストの両方）
  - ホストが `{"type":"host","name":"..."}` を返信し、クライアントは送信元 IP をホスト IP として採用
  - 自動発見が使えない環境では、設定画面でホスト IP を手入力できます（ホスト側の画面に自端末の IP が表示されます）

### 同期の堅牢化（v1.5〜）

「たまに同期されない」対策として、同期を閉ループ化しました。

- **ホスト自身の残量は一覧・通知に入れません**（v1.5 で仕様変更。ホストでは自端末の監視も行いません）
- **ACK＋再送**: ホストはレポート受信時に ACK を返します。クライアントは ACK が来なければ最大3回再送します（従来は UDP を1回送るだけで、パケットが落ちると次の機会までずれていました）
- **自動再発見**: ACK が全滅したら、ホストの IP が変わった可能性を疑って自動発見をやり直し、見つかれば IP を更新して送り直します（再発見は最短120秒間隔）。従来は IP が変わると手動で再発見するまで永久に未同期でした
- **スロットル時の遅延送信**: 残量変化が15秒スロットルの期間に来ても捨てず、期限が来たら送ります
- **ハートビート短縮**: 60秒 → 30秒
- **同期状態の可視化**: クライアントの常駐通知に「最終同期: ○秒前／未同期」を表示します
- **Wi-Fiロック／マルチキャストロック**: 常駐中は両ロックを保持し、画面OFFやWi-Fi省電力での受信落ちを抑えます（電池消費との引き換えです）
- **BLEウォッチドッグ**: ホストのスキャンとクライアントのアドバタイズを30秒ごとに点検し、止まっていれば再開します。Bluetooth の OFF→ON にも追随して自動再開します

### バックグラウンド継続（v1.4〜）

常駐アプリなので、止められないための仕組みを明示的に入れています。

- 本体はフォアグラウンドサービス（常駐通知あり）＋ `START_STICKY` で動作します
- **電池最適化の除外を、サービス開始時に自動で要求**します（v1.3 まではボタンから手動で開く必要がありました）。除外しないと Doze に入ったときにサービスごと止められたり、ネットワークアクセスを制限されたりします。状態カードに「電池最適化: 除外済み／未除外」を常時表示します
- BLE スキャンは**フィルタ付き**（Manufacturer Data の先頭マジック照合）です。フィルタなしスキャンは画面 OFF 時に Android 側で配信が止まるため、バックグラウンド受信にはフィルタが必須です。オフロードフィルタ非対応端末では無フィルタにフォールバックします（その場合は画面 OFF で止まり得ます）
- 最近使ったアプリからスワイプで消された場合は、`onTaskRemoved` から AlarmManager 経由で再起動を試みます（OS の制限で弾かれる場合もあります）
- 端末再起動後は `BOOT_COMPLETED` で自動再開します（サービスが有効だった場合のみ）
- それでもメーカー独自の省電力機能（Xperia の STAMINA モード等）で強制停止された場合は、アプリ側からは復旧できません。長時間使う端末ではメーカー側設定でも除外してください

### BLE併用（v1.3〜）

Wi-Fi/UDP と並行して、近距離用の BLE 通信も使えます（設定画面の「Bluetooth（BLE）も使う」スイッチ、既定 ON）。方式は GATT 接続をしない「ビーコン型」です。

- **クライアント**: 残量を BLE アドバタイズの Manufacturer Data（Company ID `0xFFFF`）に載せて報知します。ペイロードは `'B','H', version(1), level, flags(bit0=充電中), デバイス名(UTF-8・最大17バイト)`。残量や充電状態が変わったときだけ報知データを更新します
- **ホスト**: BLE スキャン（低電力モード）で報知を受け、解釈できたものを通常のレポートとして取り込みます（警告判定・常駐通知は Wi-Fi 経由と共通）。同一デバイスから Wi-Fi と BLE の両方で届いても、名前で同一視されるため二重表示にはなりません
- **権限**:
  - Android 12+: `BLUETOOTH_SCAN`（ホスト受信）／`BLUETOOTH_ADVERTISE`（クライアント送信）／`BLUETOOTH_CONNECT` を、サービス開始時に要求します
  - Android 11 以下: スキャンに位置情報許可（`ACCESS_FINE_LOCATION`）と位置情報 ON が必要です。送信側は従来の Bluetooth 権限のみで動作します
- **制約**:
  - アドバタイズ送信（ペリフェラル動作）に対応しない端末では BLE 送信できません。その場合も Wi-Fi 通信は継続します（クライアントの常駐通知に「BLE不可」と表示されます）
  - 到達距離は同一空間レベルで、壁越しには弱いです
  - Bluetooth が OFF の端末では BLE は動作しません
  - Android 8 端末での BLE 実機動作は未確認です

### 送信タイミング（クライアント）

- 電池残量の変化時（`ACTION_BATTERY_CHANGED` を受信したとき）。ただし**15 秒のスロットル**あり
- **60 秒ごとのハートビート**（変化がなくても定期送信）
- バックグラウンド動作はフォアグラウンドサービス（種別: dataSync）で維持します

### ホスト側の動作

- 受信したレポートをデバイス名ごとに保持し、一覧表示（画面＋常駐通知）
- **常駐通知（ongoing notification）**に全デバイスの残量をリングゲージで一覧表示します（イヤホンの電池表示のイメージ）。ホスト自身の残量は含まれません（v1.5〜）
- アプリ内の一覧も同じリング表示です（リング＋端末名＋状態テキストのシンプルな行レイアウト）
- 180 秒以上レポートがないデバイスは「（応答なし）」と表示します（一覧から消去はしません）

### リング表示の仕様（v1.1〜、v1.2でコントラスト改善）

- Android 標準の通知には円形プログレスがないため、Canvas で円弧を描いたビットマップをプログラム生成し、RemoteViews で通知に組み込んでいます
- リングは「グレーのトラック（全周）＋残量ぶんの円弧（真上起点・時計回り）＋中央に残量数値」で構成します
- 色分けは最小限です:
  - **15% 未満: 赤**
  - **20% 以下: 橙**
  - **それ以外: 単色（明背景=濃いグレー／暗背景=ほぼ白）**
  - 応答なしのデバイスはリング全体を薄く（グレー＋alpha 低下）表示し、名前の下に「応答なし」と出ます
- **v1.2 の修正**: v1.1 は明背景前提の濃いグレー（#616161）で描画していたため、ダークな通知シェード上では円弧・中央数値・端末名がほぼ見えなかった（実機スクショで確認）。v1.2 では端末のナイトモード判定に合わせて明／暗の2パレットを切り替え、通知の文字色も RemoteViews の `setTextColor` で明暗に合わせて明示指定するようにした。リング表示サイズも 44dp → 56dp に拡大し、線幅も太くした

### アプリ内 UI（v1.2〜）

- アクションバーを廃止し、画面内ヘッダーに統一（タイトル重複の解消）
- 画面を「状態カード／設定カード／操作ボタン／デバイス一覧」のブロック構成に再編。デバイス一覧の各行もカード型にした
- 配色はダーク基調で固定（背景 #0F1113、カード #1B1E23、文字 #F2F3F5／#B9BEC6）＋アクセント1色（青 #6CB2F5）。「サービス開始」だけをアクセント色のプライマリボタンにし、他のボタンはサブボタンで統一
- 状態表示は「サービス: ● 実行中／○ 停止中（役割）」形式に整理。入力欄は枠付きの面として描画する
- 常駐通知での表示上限:
  - **最大 5 台**までリングを横並び表示します（下に端末名、充電中は「充電中」の小ラベル）
  - **6 台目以降**は通知下部にテキスト行（`名前: 85%（充電中）` 形式）で併記します
- カスタムビューが使えない表示先（ロック画面の一部など）向けに、通知の本文には `名前 85% / 名前 62% …` の一行サマリも併せて設定しています

### 警告通知の条件

- いずれかのデバイス（ホスト自身を含む）が **15% 未満** になったら、ホストに警告通知を出します
- **連打防止**: 警告はデバイスごとに 1 回だけ出し、そのデバイスが **20% 以上に回復するまで再通知しません**（回復後に再度 15% を切ったらまた通知します）

### 永続化・自動開始

- 役割・デバイス名・ホスト IP・サービス有効フラグを SharedPreferences に保存します
- サービスを有効にした状態で端末を再起動すると、`BOOT_COMPLETED` でサービスを自動再開します

## インストール方法

配布物はデバッグ署名済み APK です。

```
BatteryHub-debug.apk
```

1. APK を各 Android デバイスにコピーする
2. ファイルを開いてインストールする（初回は「提供元不明のアプリ」の許可が必要な場合があります）

コマンドライン派は、PC から:

```
adb install BatteryHub-debug.apk
```

## 使い方

### ホスト側（メインの Xperia など）

1. アプリを開く
2. 役割で「ホスト」を選ぶ
3. この端末の名前を入力する（例: `Xperia 1 II`）。画面に表示される「この端末のIP」を控えておくと手入力設定に使えます
4. 「サービス開始」を押す（初回は通知許可ダイアログで許可する）
5. 「電池最適化の除外を要求」ボタンから除外しておく（推奨。下記参照）
6. 他デバイスの残量は、画面の一覧と常駐通知で確認できます

### クライアント側（他の各デバイス）

1. アプリを開く
2. 役割で「クライアント」を選ぶ
3. この端末の名前を入力する（例: `Pixel 8`）
4. ホスト IP を設定する:
   - 「自動発見」ボタンを押す（ホスト側でサービス開始済みであること）、または
   - ホストの IP を手入力する
5. 「サービス開始」を押す（初回は通知許可ダイアログで許可する）
6. 「電池最適化の除外を要求」ボタンから除外しておく（推奨）

## 必要な権限と注意点

APK に含まれる権限（`aapt dump badging` で確認済み）:

| 権限 | 用途 |
|---|---|
| INTERNET | LAN 内 UDP 通信 |
| ACCESS_NETWORK_STATE / ACCESS_WIFI_STATE | ネットワーク状態とサブネットブロードキャスト計算 |
| FOREGROUND_SERVICE / FOREGROUND_SERVICE_DATA_SYNC | 常駐サービス（targetSdk 34 の FGS 規制対応） |
| POST_NOTIFICATIONS | 常駐通知・警告通知（Android 13+ は初回に許可が必要。Android 12 以下では宣言しても無視され、通知は標準で表示される） |
| RECEIVE_BOOT_COMPLETED | 再起動後の自動再開 |
| REQUEST_IGNORE_BATTERY_OPTIMIZATIONS | 電池最適化の除外をユーザーに要求するため |
| WAKE_LOCK | 送信処理中のスリープ抑制 |
| BLUETOOTH / BLUETOOTH_ADMIN | BLE併用（Android 11以下向けの従来権限） |
| BLUETOOTH_SCAN / BLUETOOTH_ADVERTISE / BLUETOOTH_CONNECT | BLE併用（Android 12+、ランタイム許可） |
| ACCESS_FINE_LOCATION | BLEスキャン（Android 11以下で必要） |

注意点:

- **電池最適化の除外を強く推奨**します。除外しないと、機種によっては Doze でハートビートが止まり、「応答なし」表示や警告の遅延が起きやすくなります（特にクライアント側）。
- **Android 8 端末での注意**:
  - フォアグラウンドサービスの「種別（dataSync）」は Android 14 で導入された概念です。Android 8 では種別なしの通常のフォアグラウンドサービスとして動作します（マニフェストの種別属性や種別用権限は旧 OS では無視されます）。動作に支障はありません。
  - 通知の許可ダイアログはありません（Android 13 で導入）。通知のオン／オフや重要度は、システム設定のアプリ情報→通知（チャンネル単位）で管理してください。チャンネルは Android 8 からあるため本アプリの2チャンネル（常駐ステータス／低下警告）はそのまま使えます。
  - Android 8 はバックグラウンド実行制限が導入された世代のため、サービス開始直後に常駐通知が出ていることを必ず確認してください（出ていればフォアグラウンドサービスとして正常に維持されます）。
- 同一 LAN 前提です。ルーターの AP アイソレーション（クライアント分離）が有効だと端末同士が通信できません。
- UDP のため、到達保証はありません。ハートビート（60 秒）で回復する設計です。
- 通信は平文 JSON で認証もありません。自宅 LAN など信頼できるネットワークでの使用を想定しています。
- ホストを変える場合は、クライアント側のホスト IP を変更（または自動発見を再実行）してください。

## ビルドについて

ソースは Gradle プロジェクトとして構成しています（`settings.gradle` / `app/build.gradle`、AGP 8.5.2 / Gradle 8.7 / JDK 17 想定）。通常の開発環境では:

```
gradle assembleDebug
```

でビルドできます。

ただし、この成果物をビルドした VM では、Muse の権限設定（Direct network protocols の `other_tcp` が Deny）のため、Gradle デーモンとのローカル TCP 通信が遮断され、Gradle ビルドが開始できませんでした。そのため同梱の **`build-manual.sh`** で、公式 build-tools のチェーン（aapt2 → javac → d8 → zipalign → apksigner）により等価なデバッグ署名 APK を生成しています。Gradle でビルドしたい場合は、Muse 設定 → Permissions → Direct network protocols で `other_tcp` を Ask に切り替えてください。

ビルド環境（この VM に構築済み）:

- JDK 17.0.21（Microsoft OpenJDK）: `~/tools/jdk17`
- Android SDK（platforms;android-34 / build-tools;34.0.0 / platform-tools）: `~/tools/android-sdk`
- Gradle 8.7: `~/tools/gradle-8.7`

  - Android 8 端末でサービスが維持され、レポート送信が続くか
- 自動発見はブロードキャストを使うため、ルーターや AP の設定によっては届かない場合があります。その場合も手入力 IP で全機能が使えます。
- デバイスの同一性は「デバイス名」で判定しています。同名のデバイスが 2 台あると 1 台に混ざります。名前は重複しないよう付けてください。
- 警告の判定はホストが受信した最新値に対して行います。クライアントが圏外・電源断の場合は、最後の値に基づいて表示されます（「応答なし」表示で判別できます）。
- デバッグ署名の APK です。配布用に使う場合は、固有のキーストアでリリース署名してください。
